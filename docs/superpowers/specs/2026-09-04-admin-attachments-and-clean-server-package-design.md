# FastQQ 后台附件访问与全新服务器迁移包设计

日期：2026-09-04

## 目标

1. 管理员在聊天记录和文件资产页中可以查看图片、放大图片并下载聊天附件。
2. 构建系统生成一个可复制到其他 Windows 电脑的“全新服务器迁移包”。
3. 迁移包只迁移软件，不携带当前服务器的账号、聊天、好友、上传文件、日志、备份、后台密码或临时状态。
4. 新电脑允许由用户按照说明手动安装运行环境，不要求捆绑 Node.js 或 Python。

## 当前问题

- 主服务上传目录是项目根目录下的 `uploads/`。
- 后台管理服务错误读取 `public/uploads/`，因此文件资产列表与清理逻辑无法对应真实附件。
- 聊天记录将 `/uploads/...` 直接用作图片和下载地址；在后台页面中，该相对地址会请求管理端口 3001，而不是主服务端口 3000。
- 当前 `dist/` 只有管理程序与客户端分发物，没有一份明确排除业务数据的服务器软件包。

## 方案一：后台附件访问

### 存储路径

后台统一使用项目根目录的 `uploads/`，与主服务上传接口保持一致。文件资产统计、列表、删除和孤立文件清理全部基于该目录。

### 鉴权读取接口

新增受后台会话鉴权保护的附件读取接口。接口只接受附件文件名，服务端使用 `path.basename` 归一化并验证最终路径仍位于 `uploads/` 内。

- 图片默认以内联方式返回，可用于缩略图与灯箱预览。
- 普通文件可以作为附件下载。
- 文件不存在返回 404。
- 路径穿越、目录请求和无效文件名返回 400。
- MIME 类型由扩展名映射，未知类型使用 `application/octet-stream`。

### 前端展示

后台前端通过带 Bearer Token 的 XHR 获取 Blob，再使用临时对象 URL 展示或下载，避免在 URL 中泄露后台令牌。

- 聊天记录：图片显示缩略图并可放大；文件显示文件名、大小和下载按钮。
- 文件资产：图片缩略图与下载按钮复用同一鉴权读取接口。
- 页面刷新或重新渲染时释放不再使用的对象 URL，避免长期占用内存。
- 加载失败时显示明确占位提示，不破坏整张消息表。

## 方案二：全新服务器迁移包

### 构建产物

全量构建后在 `dist/` 生成：

`极速QQ-全新服务器迁移包.zip`

### 包含内容

- `admin/`、`src/`、`public/` 运行所需文件。
- `package.json`。
- 服务端管理程序与启动、停止脚本。
- 公网联机所需的 `cloudflared.exe` 和脚本。
- 新电脑部署说明。
- 环境检查脚本。
- 创建空目录所需的占位文件或首次启动目录初始化逻辑。

### 明确排除

- `qq_chat.db`。
- `uploads/` 中的现有文件。
- `logs/`、`backups/`、`test-logs/`。
- `admin-config.json`、`public-url.json`。
- 测试源码、开发临时文件和现有客户端分发压缩包。
- APK 私钥等只用于重新构建客户端、与运行服务器无关的敏感构建材料。

### 新电脑部署流程

1. 安装部署说明指定版本范围的 Node.js。
2. 解压迁移包到普通可写目录，避免放入需要管理员写权限的系统目录。
3. 运行环境检查脚本，确认 Node.js、必要文件和端口状态。
4. 双击服务端管理程序或启动脚本。
5. 主服务首次启动时创建空数据库与空上传目录。
6. 打开后台管理页，设置新的后台密码。
7. 按需开放 Windows 防火墙端口或启用 Cloudflare Tunnel。

部署说明必须同时解释局域网访问、端口占用处理、防火墙提示和首次后台初始化。

## 错误处理与安全边界

- 构建迁移包前使用固定白名单收集文件，不从项目根目录做无差别复制。
- 构建完成后自动检查 ZIP 中不存在数据库、账号配置、日志、上传文件和签名私钥。
- 环境检查失败时只报告问题，不修改系统环境、不自动安装软件。
- 附件接口不得读取 `uploads/` 之外的任何文件。
- 本次功能不修改或迁移现有生产数据库。

## 测试与验收

### 后台附件

- 自动化测试先证明当前后台指向错误目录且附件读取接口不存在。
- 修复后验证真实 `uploads/` 中的测试图片可以通过鉴权接口读取。
- 未登录请求被拒绝；不存在文件与路径穿越请求按预期返回错误。
- 浏览器验收聊天图片预览、灯箱放大、文件下载和文件资产页。

### 迁移包

- 自动化测试验证白名单和排除规则。
- 构建后的 ZIP 必须包含主服务、管理服务、管理程序、启动脚本和部署说明。
- ZIP 必须不包含 `qq_chat.db`、真实上传内容、日志、备份、后台配置和 APK 私钥。
- 将 ZIP 解压到独立临时目录，运行环境检查，并用隔离端口启动主服务与后台。
- 验证首次启动创建全新空数据库，前台与后台 HTTP 接口可访问。

## 不在本次范围

- 不迁移旧账号、聊天、好友关系或上传附件。
- 不在迁移包中捆绑 Node.js、Python 或自动安装运行环境。
- 不制作旧数据导出/导入向导。
- 不修改手机客户端或电脑客户端的账号数据。
