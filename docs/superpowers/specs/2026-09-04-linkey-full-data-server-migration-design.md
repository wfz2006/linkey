# Linkey 完整数据服务器迁移设计

## 目标

在保留现有“全新空服务器迁移包”的基础上，新增可从正在运行的 Linkey 服务器导出的完整数据迁移包。用户把压缩包复制到另一台 Windows 电脑并解压后，只需手动准备 Node.js 环境，即可继续以原账号、好友关系、群聊、聊天记录和附件数据运行服务器。

## 方案选择

采用“一键完整迁移包”方案。导出过程先创建 SQLite 一致性快照，再组合服务器程序、数据和附件，避免直接复制运行中的数据库。桌面管理器与后台管理页面使用同一套导出逻辑。

不采用以下方案：

- 仅导出数据：需要用户先部署空服务器并执行额外导入步骤，容易放错目录。
- 停服后复制目录：存在遗漏、停机时间和误复制日志或临时状态的风险。

## 用户入口

### 后台管理页面

在“数据备份”区域新增“导出完整迁移包”按钮。点击后先显示隐私提示，明确压缩包含账号、聊天记录以及聊天图片和文件。用户确认后开始导出，并显示进行中、成功或失败状态。

成功后显示生成文件名、大小、创建时间和服务器本地保存位置。浏览器界面不直接传输数百兆文件；用户通过服务器电脑上的 `dist` 目录取得压缩包。

### Windows 服务端管理器

在“运维工具”页面新增“完整数据迁移”卡片。点击后显示相同的隐私提示，再调用本机后台导出接口。成功后打开 `dist` 目录并选中生成的压缩包。

## 输出文件

文件名采用：

`Linkey-完整数据迁移包-YYYYMMDD-HHMMSS.zip`

压缩包根目录采用：

`Linkey-完整数据服务器/`

同一时间只允许一个迁移导出任务。已有任务运行时再次请求返回“迁移包正在生成”，不重复启动。

## 包含内容

完整迁移包包含：

- Linkey 服务端与后台程序文件。
- `Linkey-服务端管理系统.exe`。
- 经过在线快照得到的 `qq_chat.db`。
- `uploads/` 下全部聊天图片和文件。
- `admin-config.json` 中的后台密码哈希及运维配置。
- 启动脚本、环境检查脚本和部署说明。
- 新生成的 `迁移清单.json`。
- 空的 `logs/` 和 `backups/` 目录。

SQLite 数据库已经包含账号、好友关系、好友申请、群聊、群成员、聊天记录和相关业务数据，因此这些内容随数据库快照整体迁移。

## 排除内容

完整迁移包不包含：

- 运行日志和历史数据库备份。
- `test-logs/`、`tests/`、开发缓存和构建缓存。
- `public/downloads/` 下的客户端分发包。
- `public-url.json` 等临时公网隧道地址。
- APK 签名私钥和其他开发密钥。
- 旧的迁移压缩包或其他 `dist` 构建产物。

## 数据一致性

导出接口首先调用现有 SQLite 在线备份能力，得到独立的数据库快照文件。压缩包只读取该快照，不直接读取正在使用的 `qq_chat.db`。

附件文件在数据库快照完成后复制。导出期间新上传的附件可能不属于该次快照；导出程序根据快照内的附件引用核对所需文件，发现引用文件缺失时终止导出并报告具体文件，不交付不完整压缩包。未被数据库引用但仍位于 `uploads/` 的现有文件也随包保留，避免历史兼容数据丢失。

导出过程不停止主服务，也不修改生产数据库或附件。

## 管理员安全处理

迁移后沿用原后台管理员密码。压缩包保留 `passwordHash` 和其他必要设置，但用新的随机值替换 `sessionSecret`。因此原密码仍可登录，新电脑首次启动后原电脑浏览器中保存的后台登录令牌不能继续使用。

迁移包不会记录或导出明文管理员密码。

## 迁移清单

`迁移清单.json` 至少包含：

- 格式版本和 Linkey 版本。
- 导出时间。
- 数据库快照文件大小及 SHA-256。
- 附件总数和总大小。
- 每个附件的相对路径、大小及 SHA-256。
- 导出源的应用版本，不包含机器用户名或绝对路径。

新电脑启动前的环境检查脚本读取清单，验证数据库和附件是否存在，并校验数据库 SHA-256。完整的逐附件校验作为可选深度检查，避免每次启动都因大量附件而过慢。

## 后台接口

新增管理员认证接口：

- `POST /api/admin/migration/export`：启动并等待一次完整迁移导出，成功返回文件名、大小、创建时间和相对保存位置。
- `GET /api/admin/migration/status`：返回当前任务状态、阶段、错误信息和最近一次成功结果。

接口继续支持桌面管理器使用 `X-Linkey-Local: 1` 从回环地址调用。非本机访问必须通过后台登录令牌认证。

## 错误处理

- 数据库不存在、备份失败或完整性检查失败：停止导出，不创建最终文件。
- 引用附件缺失：停止导出并列出缺失附件。
- 磁盘空间不足或压缩失败：删除临时目录和未完成文件。
- 管理配置不存在：允许导出，但新电脑首次启动时要求设置管理员密码。
- 导出中途失败：保留原数据库、附件和既有迁移包，不覆盖任何生产数据。

最终压缩包先写入临时文件，全部验证通过后再原子重命名为正式文件名。

## 新电脑恢复流程

1. 把完整数据迁移包复制到新电脑。
2. 解压到普通可写目录，例如 `D:\Linkey-Server`。
3. 手动安装 Node.js 24 或更高版本。
4. 运行“检查服务器环境.ps1”，默认进行数据库和关键文件校验。
5. 双击 `Linkey-服务端管理系统.exe`。
6. 使用原后台管理员密码登录，并检查账号、好友、聊天记录和附件。

不提供自动覆盖已有服务器数据的“导入”按钮。完整迁移包本身就是可运行服务器目录，从而避免用户误把迁移数据覆盖到另一套正在使用的服务器上。

## 测试与验收

自动测试覆盖：

- 完整包包含数据库快照、账号与聊天相关表、附件和管理配置。
- 完整包不包含日志、历史备份、临时公网地址、测试数据或签名私钥。
- 生产数据库在导出前后内容和修改时间不被导出逻辑改写。
- 导出的 `sessionSecret` 与源配置不同，而 `passwordHash` 保持一致。
- 数据库与附件校验值正确。
- 缺少引用附件时导出失败且不留下正式压缩包。
- 并发导出请求只运行一个任务。
- 管理页面和桌面管理器都能触发同一导出流程并显示结果。
- 在临时目录解压后，环境检查通过，Node 服务能读取迁移数据库和附件。
- 现有空服务器迁移包继续生成，并继续确认不包含业务数据。

验收成功条件：在隔离测试目录中创建账号、好友关系、聊天文字、聊天图片和文件，导出完整迁移包后在另一隔离目录启动服务；原账号可以登录，好友与群聊存在，聊天记录完整，图片可预览、文件可下载，原后台密码可用且旧会话令牌失效。
