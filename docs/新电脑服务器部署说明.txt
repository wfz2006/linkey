============================================================
             Linkey 服务器部署与完整迁移说明
============================================================

“Linkey-全新服务器迁移包”只包含服务器软件，不包含原电脑上的账号、聊天记录、
好友关系、图片、文件、日志、备份或后台密码。
以下第一至第六节适用于全新服务器；保留旧数据请按第七节操作。

一、准备环境

1. 新电脑需为 Windows 10/11 64 位系统。
2. 前往 https://nodejs.org/ 安装 Node.js 24 LTS 或更高版本。
3. 安装完成后重新打开资源管理器或命令窗口。
4. 将压缩包完整解压到普通可写目录，例如 D:\Linkey-Server。
   不建议放到 Program Files 等需要管理员权限才能写入的目录。

二、首次启动

1. 右键“检查服务器环境.ps1”，选择“使用 PowerShell 运行”。
2. 检查通过后，双击“Linkey-服务端管理系统.exe”。
3. 管理程序会启动后台管理服务，并由后台启动聊天主服务。
4. 浏览器打开 http://localhost:3001，首次进入时设置新的后台密码。
5. 浏览器打开 http://localhost:3000，确认聊天前台正常显示。

首次运行会自动创建全新的 qq_chat.db、uploads、logs 和 backups，
不会出现旧电脑上的任何账号或聊天数据。

三、局域网访问

同一 Wi-Fi/局域网内的其他设备使用：

  http://服务器电脑的局域网IP:3000

如 Windows 防火墙询问是否允许 Node.js 通信，请只勾选“专用网络”。
可在命令提示符运行 ipconfig 查看服务器电脑的 IPv4 地址。

四、端口被占用

聊天主服务使用 3000 端口，后台管理使用 3001 端口。
如果环境检查提示端口已占用，请先关闭占用端口的旧程序，或在
任务管理器确认对应程序后再结束它，不要盲目终止所有 Node 进程。

五、外网联机

需要让不同网络的朋友访问时，可在后台管理页面开启 Cloudflare
Tunnel，或双击“开启外网联机.cmd”。将生成的 HTTPS 地址发给朋友。

六、停止服务

优先使用管理程序中的停止功能；也可以运行 admin-stop.cmd。

注意：本迁移包不捆绑 Node.js、Python，也不会自动安装或修改系统环境。

七、保留原聊天记录的完整迁移

使用后台“备份管理”或桌面管理器的“完整数据迁移”功能导出
Linkey-完整数据迁移包-时间戳.zip。该包包含账号、好友、群组、聊天记录、
uploads 内的图片与文件，并保留后台密码；新服务器需要重新登录后台。
压缩包包含私密聊天数据，请妥善保管。

1. 手工准备新电脑的 Windows 10/11 64 位及 Node.js 24 环境。
2. 停止旧电脑的聊天主服务（保留后台管理服务用于导出），避免最终迁移
   期间继续产生消息；然后导出最终完整迁移包。
3. 将 ZIP 复制到新电脑，解压到全新可写目录，勿覆盖已有服务器目录。
4. 首次启动前在解压目录运行：
   powershell -NoProfile -ExecutionPolicy Bypass -File .\检查服务器环境.ps1 -DeepMigrationCheck
   默认检查数据库 SHA256、附件存在性和大小；DeepMigrationCheck 逐个检查附件 SHA256。
5. 校验通过后启动管理器，使用原后台密码登录，检查旧聊天及图片、文件。
6. 更新客户端使用的新服务器地址。确认完成后仍保留旧机目录及迁移 ZIP 备份。

迁移清单是导出时的校验基准。服务器运行后数据库改变、不再匹配原清单是
正常情况；清单用于首次启动前验收，不应据此覆盖或删除运行中的数据。
再次迁移时重新导出即可。导出目录所在磁盘需支持硬链接（Windows 建议 NTFS），
因为导出使用硬链接安全发布 ZIP，避免覆盖同名文件；不支持的文件系统会导出失败。
后台管理端口 3001 只应供可信管理设备访问，不得经允许外部伪造
X-Linkey-Local / X-FastQQ-Local 头的本机反向代理暴露。
